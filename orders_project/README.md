# orders_project: a practice dbt project

A small dbt project that runs on your own computer with DuckDB. You don't need a cloud account.

```
seeds/raw_orders.csv  →  stg_orders  →  customer_revenue
   (raw data)            (cleans it)      (revenue per customer)
```

## The easy way: run.ps1

Open a terminal in VS Code (Ctrl+`) in this folder and run:

```powershell
.\run.ps1            # build everything
.\run.ps1 fresh      # wipe the database and rebuild from scratch
.\run.ps1 show       # see customer_revenue (or: .\run.ps1 show stg_orders)
.\run.ps1 test       # run only the tests
.\run.ps1 docs       # open the docs and lineage graph (Ctrl+C to stop)
.\run.ps1 help       # list these commands
```

## Commands

| Command | What it does |
|---|---|
| `dbt seed` | Loads `seeds/raw_orders.csv` into the database as the raw table. Run this first. |
| `dbt run` | Builds all models. |
| `dbt test` | Runs the data tests in `models/staging/schema.yml`. |
| `dbt build` | Seeds, runs and tests everything in the right order. |
| `dbt show --select customer_revenue` | Shows the rows of a model in the terminal. |
| `dbt run --select stg_orders` | Builds just one model. |
| `dbt docs generate` then `dbt docs serve` | Opens a docs website with the lineage graph. |

## What each file does

| File | Purpose |
|---|---|
| `dbt_project.yml` | Project settings. Staging models build as views, mart models as tables. |
| `profiles.yml` | How to connect to the database (the local file `dev.duckdb`). |
| `seeds/raw_orders.csv` | The messy raw data. In a real job, another tool would load this. |
| `models/staging/sources.yml` | Declares the raw table so models can use `source('shop', 'raw_orders')`. |
| `models/staging/stg_orders.sql` | Model 1: renames columns, converts cents to dollars, lowercases status. |
| `models/staging/schema.yml` | Tests: `order_id` is unique and not null; `status` is only completed or cancelled. |
| `models/marts/customer_revenue.sql` | Model 2: completed orders and revenue per customer, built from `ref('stg_orders')`. |

`target/` and `dev.duckdb` are generated by dbt. You can delete them at any time. Then run `dbt seed` before `dbt build`, because a model that reads with `source()` doesn't wait for the seed to load.

## Things to try

1. Add a row to `raw_orders.csv`, then run `dbt build` and `dbt show --select customer_revenue`.
2. Add a row with status `refunded` and run `dbt build`. The `accepted_values` test fails. Read the error, then fix the data or the test.
3. Change `customer_revenue` to a view by adding `{{ config(materialized='view') }}` at the top of the file.
4. Write a new model, `models/marts/daily_revenue.sql`, that totals revenue per `order_date`.
